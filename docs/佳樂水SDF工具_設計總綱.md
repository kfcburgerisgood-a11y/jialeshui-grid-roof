## 2　知識基礎（已經確定、不必再重新研究的內容）

### 2.1　SDF 慣例
- SDF(p) = 點 p 到邊界的最短距離，帶正負號。本專案統一：**內部為負、邊界為 0、外部為正**。
- 圓／球：SDF(p) = ‖p − c‖ − r。
- 聯集 min(a, b)；交集 max(a, b)；差集 max(a, −b)；平滑聯集 smooth_min(a, b, k)。
- **平滑聯集之後，融合區的數值不再是精確距離**。正確說法是「SDF 衍生的隱式設計場」。
- 梯度方向 ≈ 表面向外的法線。

### 2.2　TPMS 的限制
- Gyroid 等 TPMS 的三角函數公式是隱式場，**數值不是毫米距離，不能直接拿來當壁厚**。要控制壁厚，必須先重建成距離場，再檢查厚度。
- sheet（曲面加厚成薄壁）與 network（填實一側、另一側留孔）是兩種不同做法。
- 單元大小（cell size）不能像厚度一樣連續漸變：只能扭曲座標（單元變形），或融合兩組格構（交界可能破碎）。
- 裁切、加厚之後，兩個子空間是否仍然連通，要重新檢查，不能沿用「無限延伸」的數學性質。

### 2.3　老師文章《What these tools do》的重點
- 三種幾何表示各有分工：**場（SDF）**負責形態、厚度、孔隙；**網格（mesh）**負責分片、編號、展開、切割；**空間網格（grid）**負責日照、天空可視率、積水與水流分析。
- 七個技術警告：每個數據都要附解析度；一個特徵至少要約 3 個 voxel；用毫米不用步數；曲率控制要對應實際尺度；最小厚度要檢查而不是目測；不要逐點截斷生長速度；輸出前檢查封閉、碎片、薄壁、懸空與密閉空腔。
- 影響成本的常常不是面板總數，而是**面板種類數**。完全自由、不重複的多孔表面可能最貴。
- 工具不知道接縫、公差、組裝順序、防水、維修。從「連續的數位物件」到「建築」之間的落差，必須由我們自己補。

### 2.4　案例對照（只取策略，不取外形）
| 案例 | 提供的策略 |
|---|---|
| Parametricism（Schumacher） | 參數之間互相關聯；空間是可被閱讀的語言 |
| Chrysalis（Cameron Wu） | 可展曲面、測地線板條，把「可製造」寫進幾何規則 |
| PILOTI（THEVERYMANY） | 連續形態離散成大量薄板 |
| Duality（Ya Gao） | 材料容差吸收幾何誤差 |
| ZHA for Neutra | 侵蝕作為減材邏輯，SDF 最直接的應用 |
| 臺中國家歌劇院、阿布達比羅浮宮 | 孔洞是可停留的空間／孔隙是環境濾器 |

**一句總結：SDF 可以生成形，但不能直接生成建築。** 它不能單獨解決可展性、材料變形、屈曲、分片、接頭與施工。

## 4　基地環境判讀（會影響規則）

- **風**：幾乎單一方向，最強的是 ENE，其次是 NE。岩盤帶大致呈西南–東北走向，所以**風幾乎與海岸平行**。量體也大致沿這個方向排列，下風處的量體會被上風處擋住。
- **鹽分**：模型裡岩盤破碎、多孔的部分集中在面海的東南緣，而不是迎風的東北端。推論是鹽分主要來自浪花打上面海側，而不是隨風吹過來。**這個推論的前提是地形模型是實測或掃描的，待確認。**
- **日照**：北緯約 22°，太陽全年很高，夏至中午略偏北。季節造成的方向差異小，一天內的東西擺動大。所以：
  - 日照時數要拆成上午與下午兩張場。
  - 北向斜面在夏天也會被直射。
  - 光孔比較像「時鐘」而不是「日曆」：設計變數主要是「幾點」。
- **光斑持續時間** ≈（孔徑 d ÷ 殼厚 t 換算成角度）÷ 15°/小時。例如孔徑 30 cm、殼厚 100 cm，約 17°，光斑約持續 1 小時（殼厚為假設值）。

## 5　規則系統（工具的核心邏輯）

### 5.0　立場
表面上每一點挖多深、挖成什麼形式，由兩組資料決定：**能不能挖（限制）**，以及**為什麼要挖（環境）**。工具只制定規則，造型是規則算出來的結果；每個結果都要能檢核。

### 5.1　輸入與約定
- 幾何：殼外表面、厚度 T(x)、法向量 n(x)（一律朝外）、梁格線、開口邊界、屋頂步道。
- 風向 u_wind：由建築指向 ENE 來風方向的單位向量。
- 太陽向量 s_k：由地面指向太陽，間隔 Δt，只取高度角 > 0 的時刻。
- 海岸向量 u_sea：由陸地指向海（看圖約為東南）。
- 所有場正規化到 0–1，在同一組表面取樣點上計算。取樣解析度分「預覽」與「輸出」兩檔。

### 5.2　第一層：硬限制（最先算，後面全部服從）
```
M(x) = 0：梁線帶、開口周邊帶、屋頂步道；其餘 M(x) = 1
dist_S(x, B) ≥ r(x) + c          表面淨距
V_cut ∩ V_keep = ∅               三維不相交（斜孔在殼內會偏移，所以表面淨距不夠）
D(x) ≤ T(x) − b_min              保留背板厚度；貫穿孔是唯一例外，只能落在梁與梁之間
```

### 5.3　第二層：環境場（只描述，不做決定）
```
W(x)     = max(0, n(x) · u_wind)                       迎風程度
W_eff(x) = W(x) × V_wind(x)                            V_wind：往來風方向打射線，被擋住為 0
α(x)     = arccos(n(x) · z)
S(x)     = clamp((α_max − α(x)) / (α_max − α_min), 0, 1)  緩坡適合度
H_am, H_pm = Σ_k V_k(x) × I[n(x)·s_k > 0] × Δt         上午／下午直射時數
salt(x)  = max(0, n(x)·u_sea) × 離岸距離衰減 × 乾濕循環   鹽分場（待查證，見 8）
F(x)     = 由水溝路徑算出的水場（到水溝距離或上游流量）
```

### 5.4　第三層：依序放置，**光孔 → 水溝 → 種植穴 → 風化蜂窩**
**先放的佔位，後放的把已經放好的元素當成新禁區**（套用 5.2 的淨距規則）。排序依據：越深、越少、越難移動的越先放。

1. **光孔（反向設計）**：輸入「希望光斑落在哪裡 y」與「哪個時刻 t」，反算孔位 x = y + λ·s(t)（λ > 0），孔軸 = s(t)。同時刻的孔一定互相平行。x 必須落在 M = 1。檢核光斑誤差 e = ‖y_actual − y_target‖ ≤ e_max。孔外緣有一圈凸緣擋水。
2. **水溝**：從起點沿表面最陡下降方向（−z 投影到切平面）前進，受吸引點與排斥點影響，繞開光孔凸緣；溝寬隨累積流量加寬。同時產生水場 F(x)。**這一項還沒有正式公式，是下一個要補的地方。**
3. **種植穴**：
   - 必要條件（任一不符就排除）：M = 1；T − b_min ≥ 根系需求深度 R_j；有排水出口；可以維護。
   - 適合度：G_j = (1 − W_eff)^a_j × S^b_j × L_j(H) × K_j(F)；G_j ≥ τ_j 列為候選，同一點取 G_j 最高的類別。
   - 深度直接等於 R_j。j 先定義為生長環境類型（曝露乾燥／遮蔽濕潤／邊緣垂掛），物種之後再查。
4. **風化蜂窩**：填在剩下的區域。
   ```
   d(x)  = salt(x)^p                          驅動場（不要用 W 驅動，理由見第 4 節）
   ρ*(x) = ρ_min + (ρ_max − ρ_min) × d(x)     目標密度
   r(x)  = 1 / √ρ*(x)                         可變半徑泊松圓盤取樣
   D(x)  = D_min + (D_max − D_min) × d(x)^γ   深度
   D(x) ≤ min(T − b_min, 印章最大深度)
   ρ = N_R / A_R                              只用來驗收，不用來生成
   ```
   相鄰的坑用 SDF 平滑聯集連在一起，並順著風的切向拉長。**這一步是讓結果明顯不同於「隨機撒球」的關鍵**，圖上一定要看得出差別。

### 5.5　合成與幾何
- 類型圖（每點只屬於一類）＋深度圖。
- 淺（蜂窩）：沿法線位移，是可以壓印的高度場。
- 深（水溝、種植穴、光孔）：SDF 挖除，交界用平滑最小值融合，融合半徑 k。

### 5.6　檢核
| 規則 | 判斷式 | 不符合時 |
|---|---|---|
| 背板厚度 | D ≤ T − b_min | 截斷深度並標示 |
| 淨距 | 5.2 兩條 | 後放的元素移位或刪除 |
| 光斑誤差 | e ≤ e_max | 調整 y 或時刻 |
| 根系深度 | T − b_min ≥ R_j | 改成較淺的類別或刪除 |
| 製造深度 | D ≤ 印章上限（15 cm） | **尚無對策，見第 8 節** |
| 密度驗收 | ρ ≈ ρ* | 調整取樣 |

## 6　開發方式：以老師的 grid-roof 範本為底（2026-10-27 起）

### 6.1　為什麼改走範本
老師提供的 [rccn-dev/grid-roof](https://github.com/rccn-dev/grid-roof)（建立在 [compas_vol](https://github.com/rccn-dev/compas_vol) 上）已經實作了我們規則系統的骨架。我們不從零寫，而是用 GitHub 的「Use this template」複製一份，**逐步把它的「手畫輸入」換成「環境驅動」**。

| 我們的規則 | grid-roof 已有 | 我們要換成 |
|---|---|---|
| 量體 | 18×12 m 平板（`slab`，平面高度場） | **任意封閉實體**：Rhino 手捏的 SubD → mesh → `VolGrid.from_mesh` |
| 禁挖遮罩、背板厚 | `keep`：體積式保留，每個後續步驟都不准侵犯 | 沿用；加上殼厚 T 與 b_min |
| 光孔 | 手畫輪廓（`drawing.json`），檢查實際透光面積 | 由目標光斑 y 與時刻 t 反算 |
| 水溝 | 平面上的 priority flood，依匯水面積決定溝寬溝深，檢查積水 | 改成沿曲面流動（見 6.3） |
| 種植穴 | 手畫輪廓，保證壁與底 | 由適合度 G_j 決定位置 |
| 孔隙／蜂窩 | spinodoid 泡沫，只隨「深度」漸變 | 由鹽分場 salt(x) 驅動 |
| 分件、風化、列印 | `kit`、`weathering`、`printing` | 直接沿用 |

grid-roof 的工作守則也一併採用：所有數值放在 `brief.py`（單位 mm）；每條規則在 `checks.py` 有一個檢核、在 `tests/` 有一個測試；**一次改一件事 → 從那一步往下重跑 → 看結果 → 跑測試 → commit**。

### 6.2　工作流（每一步都要有：參數、計算、確認數值、預覽）

| 步驟 | 函式（建議名稱） | 計算 | 確認數值 | 預覽 |
|---|---|---|---|---|
| 1 | `Brief` | 所有參數 | — | `print(brief)` |
| 2 | `body` | 讀入 SubD 轉出的 mesh，轉成距離場；用 Shell 做出殼厚 T | 是否封閉、尺寸與單位、體積 | 剖面圖 |
| 3 | `structure` | 梁或肋（由使用者給曲線），算出 keep 的一部分 | 梁內距離為負 | 平面＋剖面 |
| 4 | `fields` | W_eff、H_am、H_pm、S、salt，算在外表面取樣點上 | 各場 min／max／平均、直方圖、探針點 | 彩色表面 |
| 5 | `openings` | 光孔反算 | 光斑誤差 e、實際透光面積、持續時數 | 孔軸線＋光斑 |
| 6 | `water` | 水溝（v1 只處理雨水打得到的上表面；v2 沿曲面） | 積水點數、無處可去的水、最深切深 | 水溝線 |
| 7 | `planters` | 種植穴 | 每類面積、壁與底厚度 | 分區色塊 |
| 8 | `pores` | 蜂窩／孔隙，由 salt 驅動 | 實際孔隙率與目標的差 | 剖面 |
| 9 | `keep`、`design` | 合成 | 保留材料被挖掉的量（必須 0） | 剖面、keep 外框 |
| 10 | `kit`、`weathering` | 分件、風化 | 件數、最大件記憶體、接縫誤差 | 分件平面 |
| 11 | `printing.sample` | 列印樣本 | 最薄壁、懸挑 | 3D 圖 |

解析度：voxel 40 mm（或更粗）用來看；10–15 mm 用來做。**每一個數字都要附 voxel 值。**

### 6.3　水的處理：一般封閉實體上的限制
grid-roof 的排水在「平面」上解，每個平面位置只有一個高度；compas_vol 的 `Runoff` 也明寫只處理每一欄最上面的表面，底面和懸挑內側不會被處理。所以：
- 在手捏的 SubD 上，**頂面會長出水溝，陡的側牆不會**，而側牆正是我們想讓水流下來的地方。
- **v1**：先接受這個限制，水只做在雨水打得到的上表面，並在報告中寫明。
- **v2**：在外表面 mesh 上做路徑：每個頂點往最低的相鄰頂點流，累積上游流量，用流量決定溝寬溝深，再把水溝曲線做成 SDF 膠囊挖除。積水檢查沿用「每個低點都要有出路」的邏輯。

### 6.4　測試實體（SubD）的建議
- 必須是**封閉實體**，轉成 mesh 後輸出（.obj 或 .stl），單位 mm，原點放在角落。
- 準備兩個版本：**A 版沒有懸挑**（每個平面位置只有一個頂面，可以拿來和老師的方法直接對照）；**B 版有懸挑與陡牆**，用來測 v2 的水。
- 尺寸先小：約 10 × 6 × 4 m。以 voxel 40 mm 計算，約 375 萬個格點，筆電跑得動；做到 40 m 長的量體時，預覽要先改用 80 mm。

## 9　已知陷阱（兩段對話學到的）

- 平滑聯集後的數值不是精確距離；TPMS 的數值不是毫米。
- 網格越細不一定越好：TRIAD 精細版有 685 片小面板，製造問題更嚴重。
- 可以展平不等於可以施工：接頭、折邊、公差、組裝順序都還沒做。
- 簡單排版算出的板材數量不能當材料估價。
- AI 生成的渲染圖只是意象，不是模型。分鏡圖曾出現光束收斂、球形坑等錯誤，不能當作設計依據。
- 流速、積水、通風、應力在沒有模擬或實驗之前，都只能寫「設計目標」，不能寫「結果」。
- 方向向量的正負約定一錯，整張場就會顛倒；每次換資料都要先驗證。
